# 需求4：AI 板块成分股识别（核心池自动维护）— 需求文档

> 来源：AI 行业分析平台业务需求（AI 自动维护核心池 MVP → V1 → V2 路线图）  
> 版本：v1.0  
> 更新日期：2026-06-16

---

## 1. 需求背景与目标

### 1.1 背景

东财/同花顺板块成分股覆盖面广，但存在**概念蹭热点、主业占比低、产业链归属模糊**等问题。投研场景更需要的是**精选赛道（核心池）**下的**真实产业标的**，而非简单沿用交易所或行情软件的全量成分。

本需求引入 **AI 产业分析师**能力：基于公司公开资料，判断个股是否属于目标赛道、所处产业链环节及核心程度，并自动维护分级核心池。

### 1.2 核心理念

**不追求「AI 自动识别所有行业所有股票」**，而从最小可行产品（MVP）起步，逐步迭代：

| 阶段 | 范围 | 能力 |
|------|------|------|
| **MVP**（2~4 周） | 约 **50** 个核心赛道，**1000~2000** 只股票 | AI 归属判断 + 评分分级 + 核心池落库 |
| **V1** | 同 MVP 范围 | 核心池**权重**（组合构建）；规则剔除增强 |
| **V2** | 平台化扩展 | 产业链自动拆解、多维龙头、主线排行榜（对接需求1/2/3） |

### 1.3 MVP 目标示例

```text
存储芯片
├─ 江波龙          S级
├─ 佰维存储        S级
├─ 兆易创新        A级
├─ 德明利          A级
└─ 北京君正        B级

机器人
├─ 双环传动        S级
├─ 绿的谐波        A级
├─ 埃斯顿          A级
└─ 柯力传感        B级
```

### 1.4 与需求1 / 2 / 3 的关系

| 维度 | 需求1 主线板块 | 需求2 板块龙头 | 需求3 量化主线 | **需求4 核心池** |
|------|----------------|----------------|----------------|------------------|
| 分析对象 | 东财全行业板块 | 板块内个股 | 申万等行业 | **人工精选赛道** |
| 成分来源 | 行情板块成分 | `ods_dc_member_di` | 行业指数成分 | **AI 判定 + 人工维护** |
| 核心问题 | 哪个板块是主线 | 板块内谁是龙头 | Top3 量化主线 | **是否真属于该赛道** |
| 方法 | 规则因子 | 规则因子排名 | FTELP 因子 | **LLM + 规则后处理** |
| 典型输出 | 板块排名 | 五类龙头 | 启动/退潮信号 | **S/A/B/C 核心池** |

需求4 的赛道可与东财概念板块**弱关联**（作候选股初筛），但**不以东财成分为准**；V2 可将核心池与需求2 龙头、需求1 主线打通。

### 1.5 非目标（MVP 阶段）

- 不覆盖全市场 5000+ 股票、不覆盖全部申万/东财板块。
- 不提供自动下单、仓位管理。
- 不实现实时盘中刷新（默认 **T 日收盘后日批**）。
- 产业链上中下游自动拆解、主线排行榜归入 **V2**。

| 角色 | 场景 |
|------|------|

## 3. 核心业务功能

### 3.1 功能 1：股票行业归属分析

**输入**（单条或批量）：

```json
{
  "industry": "存储芯片",
  "stock": "江波龙"
}
```

或：

```json
{
  "industry_id": "TRACK_001",
  "ts_code": "301308.SZ"
}
```

**系统获取数据源**（MVP 最低集）：

| 资料类型 | 用途 | 数据来源（规划） |
|----------|------|------------------|
| 公司简介 / 主营业务 | 文本语义匹配 | `ods_stock_company_di`（待建） |
| 产品信息 | 产品–赛道映射 | 同上 / 公告摘要 |
| 财报业务构成 | 主营占比硬约束 | `ods_fina_mainbz_di`（待建） |
| 机构研报摘要 | 产业地位、受益逻辑 | `ods_report_rc_di`（已有） |

**AI Prompt 角色**：资深产业分析师。

**输出**（严格 JSON，无额外文本）：

```json
{
  "industry_match": true,
  "segment": "存储模组",
  "core_degree": "核心",
  "score": 95,
  "reason": "主营存储产品，模组出货量国内前三，深度绑定大客户..."
}
```

| 字段 | 说明 |
|------|------|
| `industry_match` | 是否属于该产业链/赛道 |
| `segment` | 所处环节（如设备/材料/模组/终端） |
| `core_degree` | 核心程度（核心/重要/一般/边缘） |
| `score` | 0~100 综合相关度 |
| `reason` | 判断依据摘要（≤500 字） |

### 3.2 功能 2：自动剔除概念股

满足以下**任一**条件，**不进入核心池**（仍可写入 AI 评分表留痕）：

| 规则 | 条件 |
|------|------|
| R-1 主业占比过低 | 财报分部收入中，与赛道相关业务收入占比 **< 10%** |
| R-2 评分过低 | AI `score` **≤ 20** |
| R-3 明确不匹配 | `industry_match = false` |

> MVP：若无分部财报，仅依赖 R-2、R-3；有 `ods_fina_mainbz_di` 后启用 R-1。

### 3.3 功能 3：核心池分级

| 等级 | 分数区间 | 说明 |
|------|----------|------|
| **S** | 90+ | 赛道核心标的，优先展示 |
| **A** | 80~89 | 重要标的 |
| **B** | 60~79 | 相关标的，观察 |
| **C** | <60 | 弱相关，**默认不进核心池** |

核心池表仅收录 **`industry_match=true` 且 score≥60（B 级及以上）** 的股票；C 级仅保留历史评分记录。

### 3.4 功能 4：核心池权重（V1）

用于组合构建，同行业核心池内归一化：

```text
weight = score / Σ(同行业核心池股票 score)
```

V1 附加因子（与 AI 分合成最终权重）：

| 因子 | 权重 |
|------|------|
| 行业相关度（AI score） | 50% |
| 市值 | 20% |
| 成交额 | 20% |
| 机构覆盖度 | 10% |

MVP 阶段 `weight` 仅按 AI `score` 比例计算。

## 4. AI Prompt 与评分规范

### 4.1 角色与任务

- **角色**：资深产业分析师  
- **任务**：判断公司是否属于目标行业/赛道的**核心标的**  
- **输出**：严格 JSON，字段见 §3.1

### 4.2 评分规则（总分 100）

| 维度 | 分值 | 说明 |
|------|------|------|
| 主营业务占比 | 40 | 相关业务收入占营收比例（有分部财报时优先） |
| 行业地位 | 20 | 龙头/重要供应商/一般参与者 |
| 产业链位置 | 20 | 是否处于赛道关键环节 |
| 受益程度 | 20 | 赛道景气对该公司的业绩弹性 |

### 4.3 行业相关度（规则层，与 AI 交叉验证）

```text
行业相关度 ≈ 主营占比（权重高）
           + 产业链位置（上/中/下游匹配度）
           + 行业关键词匹配（NLP 抽取，辅助）
```

示例：主营占比 50% + 行业龙头 + 受益最直接 → **95 分**。

### 4.4 Prompt 模板（固定骨架）

```text
你是一名资深产业分析师。
行业：{industry_name}
公司：{stock_name}（{ts_code}）

【公司简介】{company_intro}
【主营业务】{main_business}
【产品信息】{products}
【财报业务构成】{mainbz_json}
【近90日研报摘要】{report_summary}

请仅输出 JSON（不要 markdown 代码块）：
{
  "industry_match": boolean,
  "segment": string,
  "core_degree": string,
  "score": number,
  "reason": string
}
```

`model_name`、temperature、max_tokens 写入配置表，见技术文档。

## 5. 数据模型（业务层）

### 5.1 行业维表 `dim_industry_track`

| 字段 | 说明 |
|------|------|
| `industry_id` | 赛道 ID（如 `TRACK_001`） |
| `industry_name` | 赛道名称（如「存储芯片」） |
| `parent_industry_id` | 上级赛道（可空） |
| `level` | 层级（1=一级，2=二级） |
| `status` | 1=启用，0=停用 |
| `dc_board_code` | 关联东财板块代码（可选，候选股初筛） |
| `remark` | 备注 |

MVP 维护约 **50** 条启用记录。

### 5.2 股票维表 `dim_stock`

| 字段 | 说明 |
|------|------|
| `ts_code` | 股票代码 |
| `stock_name` | 股票名称 |
| `market` | 市场（SH/SZ/BJ） |
| `list_status` | 上市状态 |

可与现有 ODS 个股主数据合并，不重复维护。

### 5.3 AI 分析结果 `dwm_industry_stock_ai_score_di`

| 字段 | 说明 |
|------|------|
| `trade_date` | 交易日期（快照日） |
| `industry_id` | 赛道 ID |
| `industry_name` | 赛道名称 |
| `ts_code` | 股票代码 |
| `stock_name` | 股票名称 |
| `industry_match` | 是否匹配 |
| `segment` | 所处环节 |
| `score` | 评分 0~100 |
| `level` | S/A/B/C |
| `reason` | 判断原因 |
| `model_name` | 模型名称 |
| `prompt_version` | Prompt 版本 |
| `raw_json` | 模型原始返回 |
| `created_at` | 创建时间 |

### 5.4 核心池 `dwm_industry_stock_core_di`

| 字段 | 说明 |
|------|------|
| `trade_date` | 交易日期 |
| `industry_id` | 赛道 ID |
| `industry_name` | 赛道名称 |
| `ts_code` | 股票代码 |
| `stock_name` | 股票名称 |
| `score` | AI 评分 |
| `level` | S/A/B |
| `weight` | 赛道内权重（MVP：按 score 归一化） |
| `segment` | 产业链环节 |
| `updated_at` | 更新时间 |

## 6. 自动更新流程

### 6.1 调度

| 项 | 说明 |
|----|------|
| 时间 | 交易日 **15:30 后**（建议 18:00~20:00，ODS 同步完成后） |
| 工具 | XXL-JOB（与现有 `run_data_sync` 同 Executor） |
| 频率 | MVP：**周度**全量复核 + **日度**仅更新有公告/财报变动的股票；可配置 |

### 6.2 执行流程

```text
1. 读取 dim_industry_track（status=1）
2. 按赛道获取候选股列表（人工维护 + 东财板块初筛 + 历史核心池）
3. 拉取最新 ODS 资料（财报、研报、公司介绍）
4. 调用 AI 分析引擎（批量，限流）
5. 规则后处理（剔除概念股，计算 level）
6. UPSERT dwm_industry_stock_ai_score_di
7. 生成/更新 dwm_industry_stock_core_di（含 weight）
8. 写任务日志与失败重试队列
```

### 6.3 与现有日批的关系

```text
run_data_sync
  → …（行情、财报、研报等 ODS）
  → run_ai_core_pool_batch    # 本需求新增
```

不依赖 `dwm_dc_industry_prosperity_di` 等 DWM 景气表；可选读取需求2 龙头分作 V1 机构覆盖度输入。

输入赛道名，AI 输出上/中/下游环节及代表公司类型，写入 `dim_industry_chain_di`。

对接需求2 已有能力：

| 龙头类型 | 来源 |
|----------|------|
| 产业龙头 | 需求4 AI score + 需求2 `score_industry` |
| 资金龙头 | 需求2 `leader_fund_name` |
| 趋势龙头 | 需求2 `leader_trend_name` |

### 7.3 主线板块识别 + 排行榜

对接需求1/3：输出「存储芯片 92 / AI算力 90 / …」综合热度榜。

## 8. 验收标准（MVP）

| 编号 | 验收项 |
|------|--------|
| AC-1 | `dim_industry_track` 启用赛道数 ≥ 50（或约定首期数量） |
| AC-2 | 每赛道核心池股票数在合理区间（建议 10~50），全库 1000~2000 只 |
| AC-3 | 单股分析 API/批处理返回 JSON 字段完整，可解析 |
| AC-4 | `score≤20` 或 `industry_match=false` 不进入 `dwm_industry_stock_core_di` |
| AC-5 | S/A/B/C 分级与 score 区间一致 |
| AC-6 | 同一 `(trade_date, industry_id, ts_code)` 结果可复现（同模型同 Prompt） |
| AC-7 | 周度/日度任务可无人值守跑批，失败可重试、可告警 |
| AC-8 | Web 或 API 可按赛道查询核心池列表与 AI 原因 |
