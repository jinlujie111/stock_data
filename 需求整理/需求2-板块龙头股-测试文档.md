## 4. 数据完整性测试（P1）

### 4.1 上游 ODS 覆盖

```sql
-- 替换 @T
SET @T = '2026-06-12';

-- A. 板块资金流（枚举来源）
SELECT content_type, COUNT(*) AS cnt
FROM ods_industry_fund_flow_di
WHERE trade_date = @T
GROUP BY content_type;
-- 预期：行业约 80~120，概念约 400~500，合计与 moneyflow 接口一致

-- B. 板块指数元数据（辅助分类）
SELECT idx_type, COUNT(*) AS cnt
FROM ods_dc_index_di
WHERE trade_date = @T
GROUP BY idx_type;
-- 预期：行业板块+概念板块合计约等于 A 的合计（允许地域差异）

-- C. 成分股（按板块统计）
SELECT
  CASE idx.idx_type
    WHEN '行业板块' THEN '行业'
    WHEN '概念板块' THEN '概念'
    ELSE idx.idx_type
  END AS ct,
  COUNT(DISTINCT m.ts_code) AS board_cnt,
  ROUND(AVG(cnt.member_cnt), 1) AS avg_members
FROM ods_dc_member_di m
LEFT JOIN ods_dc_index_di idx
  ON m.trade_date = idx.trade_date AND m.ts_code = idx.ts_code
JOIN (
  SELECT ts_code, COUNT(DISTINCT con_code) AS member_cnt
  FROM ods_dc_member_di
  WHERE trade_date = @T
  GROUP BY ts_code
) cnt ON cnt.ts_code = m.ts_code
WHERE m.trade_date = @T
GROUP BY 1;
-- 预期：行业/概念 board_cnt 与 A 同量级；avg_members 多数板块 ≥ 5

-- D. 个股行情与资金流（评分依赖）
SELECT
  (SELECT COUNT(DISTINCT ts_code) FROM ods_stock_detail_di WHERE trade_date = @T) AS daily_cnt,
  (SELECT COUNT(DISTINCT ts_code) FROM ods_stock_fund_flow_di WHERE trade_date = @T) AS mf_cnt;
-- 预期：均 > 4000（全市场级）
```

**通过标准（AC-1）**：行业 + 概念板块在 `ods_dc_member_di` 有成分；允许少数板块 `<3` 只被 ETL 跳过。

### 4.2 结果表覆盖

```sql
SET @T = '2026-06-12';

-- E. 评分明细
SELECT content_type,
       COUNT(*) AS board_cnt,
       SUM(stock_cnt) AS stock_rows,
       ROUND(AVG(stock_cnt), 1) AS avg_stocks_per_board
FROM (
  SELECT content_type, industry_code, COUNT(*) AS stock_cnt
  FROM dwm_sector_stock_dragon_score_di
  WHERE trade_date = @T AND score_mode = 'mvp'
  GROUP BY content_type, industry_code
) t
GROUP BY content_type;

-- F. 板块摘要
SELECT content_type, COUNT(*) AS summary_cnt
FROM dwm_sector_dragon_summary_di
WHERE trade_date = @T AND score_mode = 'mvp'
GROUP BY content_type;

-- G. 明细与摘要板块数应一致
SELECT
  s.content_type,
  COUNT(DISTINCT s.industry_code) AS summary_boards,
  COUNT(DISTINCT d.industry_code) AS score_boards
FROM dwm_sector_dragon_summary_di s
LEFT JOIN dwm_sector_stock_dragon_score_di d
  ON d.trade_date = s.trade_date
 AND d.industry_code = s.industry_code
 AND d.score_mode = s.score_mode
WHERE s.trade_date = @T AND s.score_mode = 'mvp'
GROUP BY s.content_type;
-- 预期：summary_boards = score_boards（各类型）
```

**通过标准**：行业板块数 ≥ 抽测日 `ods_dc_member_di` 中**成分≥3**的行业板块数的 **80%**；概念同理（成分未补全时允许偏低，需备注原因）。

SET @BOARD = 'BK1036.DC';   -- 抽测行业板

## 6. 公式准确性测试（P3 · 手工验算）

对 **§2.3 行业抽测板** 取综合排名第 1、第 3 的股票各 1 只，按下列步骤在 Excel 或 Python 复算。

### 6.1 MVP 公式（与实现对齐）

```text
资金分     = 板块内百分位排名( 近20交易日 SUM(net_mf_amount) )
RS分       = min(max(RS,0), 3.0) / 3.0 × 90，其中 RS = 个股60日复合涨幅 / 板块60日复合涨幅
成交额分   = 板块内百分位排名( 近20交易日 AVG(amount) )    -- amount 单位：千元
市值分     = 板块内百分位排名( total_mv 或 close×amount 代理 )
综合分     = 0.4×资金分 + 0.3×RS分 + 0.2×成交额分 + 0.1×市值分
趋势分(MVP代理) = (RS分 + 成交额分) / 2
机构分(MVP代理) = 板块内百分位排名( 近30日研报数 )
```

百分位排名（与 `etl/sector_dragon/scoring.py` 一致）：

```text
score = 100 × (成分股中 raw ≤ 该股 raw 的个数) / (有效 raw 个数)
```

### 6.2 抽测 SQL：拉原始因子（行业板）

将 `@BOARD`、`@T` 换成抽测板块与日期；`@STOCK` 换成待验股票代码。

```sql
SET @T = '2026-06-12';
SET @BOARD = 'BK1036.DC';
SET @STOCK = '603986.SH';

-- 交易日窗口（与 ETL 一致：ods_trading_day 向前取）
SELECT trade_date FROM ods_trading_day
WHERE trade_date <= @T
ORDER BY trade_date DESC
LIMIT 65;

-- 个股 20 日主力净流入（万元）
SELECT SUM(net_mf_amount) AS fund_net_20d
FROM ods_stock_fund_flow_di
WHERE ts_code = @STOCK
  AND trade_date BETWEEN (
    SELECT MIN(d) FROM (
      SELECT trade_date AS d FROM ods_trading_day
      WHERE trade_date <= @T ORDER BY trade_date DESC LIMIT 20
    ) x
  ) AND @T;

-- 板块 60 日涨幅
SELECT EXP(SUM(LN(GREATEST(1 + pct_change/100, 1e-8)))) - 1 AS board_ret_60d
FROM ods_dc_daily_di
WHERE ts_code = @BOARD
  AND trade_date BETWEEN (
    SELECT MIN(d) FROM (
      SELECT trade_date AS d FROM ods_trading_day
      WHERE trade_date <= @T ORDER BY trade_date DESC LIMIT 60
    ) x
  ) AND @T;

-- 个股 60 日涨幅
SELECT EXP(SUM(LN(GREATEST(1 + pct_chg/100, 1e-8)))) - 1 AS stock_ret_60d
FROM ods_stock_detail_di
WHERE ts_code = @STOCK
  AND trade_date BETWEEN (
    SELECT MIN(d) FROM (
      SELECT trade_date AS d FROM ods_trading_day
      WHERE trade_date <= @T ORDER BY trade_date DESC LIMIT 60
    ) x
  ) AND @T;

-- 与落库 detail_json 对比
SELECT ts_code, stock_name,
       score_fund, score_trend, score_inst, score_composite,
       detail_json
FROM dwm_sector_stock_dragon_score_di
WHERE trade_date = @T AND industry_code = @BOARD
  AND ts_code = @STOCK AND score_mode = 'mvp';
```

### 6.4 全板块截面复算（可选，Python 一次性）

在服务器项目根目录（已 `source func.sh`）：

```bash
export PYTHONPATH=~/stock_data:~/stock_data/dw-utils
python3 - <<'PY'
from datetime import date
from etl.sector_dragon.db_util import get_engine_stock, list_boards, load_config
from etl.sector_dragon.score_mvp import score_board_mvp

T = date(2026, 6, 12)
BOARD = "BK1036.DC"  # 抽测板
engine = get_engine_stock()
cfg = load_config(engine, ["行业", "概念"])
boards = [b for b in list_boards(engine, T, ["行业", "概念"], cfg.min_constituents)
          if b["industry_code"] == BOARD]
scores, _ = score_board_mvp(engine, T, boards[0], cfg)
live = {r["ts_code"]: r["score_composite"] for r in scores}

from sqlalchemy import text
rows = engine.connect().execute(text("""
  SELECT ts_code, score_composite FROM dwm_sector_stock_dragon_score_di
  WHERE trade_date=:t AND industry_code=:b AND score_mode='mvp'
"""), {"t": T, "b": BOARD}).mappings().all()
db = {r["ts_code"]: float(r["score_composite"]) for r in rows}

diff = [(c, live.get(c), db.get(c)) for c in set(live)|set(db)
        if abs((live.get(c) or 0)-(db.get(c) or 0)) > 0.51]
print("mismatch count:", len(diff))
for x in diff[:10]:
    print(x)
PY
```

**预期**：`mismatch count: 0`（或仅成分股集合因 `member_date` 快照差 1 天导致极少数差异，需记录）。

## 11. 常见问题对照

| 现象 | 核查 SQL / 动作 |
|------|-----------------|
| 只有概念没有行业 | §4.1 C + `dc_member` 补数；重跑 `run_sector_dragon_batch` |
| 某板块无评分 | `SELECT COUNT(*) FROM ods_dc_member_di WHERE trade_date=@T AND ts_code=@BOARD` |
| 综合分与手工差 >1 | 核对 `detail_json.member_date` 是否非 @T；成分快照日不同会导致偏差 |
| API 无数据 | `SELECT COUNT(*) FROM dwm_sector_dragon_summary_di WHERE trade_date=@T`；检查 `stock_read_grants.sql` |
| dc_index 同步 0 行 | 不影响 MVP（用 moneyflow 的 content_type）；见测试文档 §4.1 A/B |
